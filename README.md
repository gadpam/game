# «ПОКА ПОВРЕМЕНИМ» · Том 1 (главы 1–5)

Вертикальный вебтун (16+) о пятнадцатилетнем центральном полузащитнике **Ветрове** из клуба **«Торпедо-2»** (Вторая лига Беларуси, Витебск) и текстовой **Системе**, которая считает в его игре то, чего не видит протокол матча.

- **Тон:** сухой, наблюдательный, живая футбольная речь без пафоса и книжных присказок.
- **Визуальные и повествовательные ориентиры:** *Solo Leveling* (REDICE Studio) и *«Я притворился футбольным гением»*.
- **Правило утверждения:** автор — единственная утверждающая инстанция; в канон ничего не входит без явного слова **«утверждаю»**. Работа идёт строго по одной главе за раз. Глава 6 не начинается до отдельного разрешения автора.

## Регламент документирования («правило 5 шагов»)

1. Каждый завершённый содержательный шаг работы (перерисовка/правка кадра, редактура текста, пересборка ленты, читательский аудит главы, утверждение главы) учитывается в счётчике в `docs/WORKFLOW_LOG.md` (`1/5 … 5/5`).
2. Каждая конкретная правка кадра или текста сразу фиксируется в `docs/QC_CH1-5_2026-11-13.md` по формуле **«глава N · кадр NN · было → стало · почему»**.
3. **Строго каждые 5 шагов** выполняется контрольная точка (**CHECKPOINT**):
   - обновляются `docs/WORKFLOW_LOG.md` (пройденные 5 шагов, открытые замечания, сброс счётчика на `0/5`), `docs/CHAPTERS.md` (раскадровка/файлы, если менялись) и `README.md` (таблица статуса и метрик);
   - проверяется чистота рабочего дерева (временные файлы и дубликаты остаются в `_backup/`, исключённом через `.gitignore`);
   - изменения фиксируются коммитом и отправляются (`git push`) в активную ветку репозитория на GitHub.
4. Внеплановая фиксация в Git также делается при утверждении целой главы («утверждаю») или по прямому запросу автора.

## Сборка конвейера

Зависимости (Python 3.11+):

```bash
pip install pillow fonttools numpy
```

Сборка только активной Главы 1 (не перезаписывает главы 2–5):

```bash
python3 build_ch1_system.py
python3 build_lettering.py
python3 -c "import build_scrolls; build_scrolls.build_ch1()"
python3 -m unittest discover -s tests -v
```

Изолированная пересборка утверждённой версии Главы 2 (не трогает legacy и другие главы):

```bash
python3 build_ch2_system.py
python3 build_ch2_lettering.py
python3 build_ch2_scroll.py
python3 -m unittest discover -s tests -v
```

Подготовительный слой активной Главы 3 (создаёт versioned-ресурсы и два проверочных пакета максимум по 10 фреймов):

```bash
python3 build_ch3_v2_insets.py
python3 build_ch3_v2_system.py
python3 build_ch3_v2_revisions.py
python3 build_ch3_v2_subbed.py
python3 build_ch3_v2_epilogue.py
python3 build_ch3_v2_bus.py
python3 build_ch3_v2_lettering.py
python3 build_ch3_v2_batch.py --start 1 --end 10
python3 build_ch3_v2_batch.py --start 11 --end 20
python3 -m unittest discover -s tests -v
```

По прямому запросу автора полную **проверочную**, неканоническую сборку можно воспроизвести отдельным режимом:

```bash
python3 build_ch3_v2_scroll.py --review
```

Он пишет только `CH3_V2_REVIEW_SCROLL_full.jpg` и `CH3_V2_REVIEW_SHEET.jpg` с маркировкой `НЕ УТВЕРЖДЕНО`. Канонические пути разрешены только после буквального авторского утверждения главы:

```bash
python3 build_ch3_v2_scroll.py --approved
```

Полная legacy-пересборка всех артефактов допустима только после открытия следующих глав для правки:

```bash
python3 build_insets.py       # 1. Кириллица на листах заявок и в тетрадях (из *_src.jpg)
python3 build_h27.py          # 2. Кадр блокнота h27_notebook.jpg (гл. 4)
```

## Неприкосновенные правила канона и авторские решения

- **Мир:** реален только Витебск; все клубы вымышлены («Торпедо-2», «Речник» и др.); Вторая лига Беларуси.
- **Герой (Ветров, 15 лет, ЦПЗ):** светло-чёрные (мягкий угольно-чёрный) волосы, спокойные серые глаза (эталон лица — `ch1/f08_eyes.jpg`); текущий игровой номер — **19**, позже он сам захочет **8**; не плачет и не кричит; мать — не более 2 реплик за том.
- **Форма «Торпедо-2»:** строго чёрно-белая — белая футболка с тонким чёрным воротом и манжетами, чёрные шорты, чёрные гетры, чёрные бутсы без брендов. В официальных матчах номер ставится крупно на спине и компактно на шортах; номер на груди не обязателен. Эмблем и спонсорских логотипов нет.
- **Футбольный реализм:** заявка на матч — 18 человек (11 старт + 7 запас); в гл. 1 Ветров выходит на `72′` при счёте `2:0` из-за дискомфорта задней поверхности бедра у стартового ЦПЗ Шатского.
- **Система:** только текст в голографическом окне в стиле *Solo Leveling* (шрифт Exo 2), без голоса, без `LEVEL UP`, XP и прогресс-баров, не более 2 панелей на сцену. В гл. 1 появляется впервые в жизни строго на `72′` при выходе на поле на пике волнения.
- **Утверждённая математика после Главы 1 v13 и вход Главы 2:** 12 характеристик (0–70), `ОБЩ` = среднее 12 (`426 / 35.50`); `ПРИНЯТИЕ РЕШЕНИЙ = 26`, первый квест провален без награды и штрафа; `ИВ = 68`. Обозначения кредитов `+N` в кадре не печатаются; навсегда растут не более 3 разных характеристик в месяц; старые 6 метрик и слово «ЯКОРЬ» запрещены. Старые панели Главы 2 с `ОБЩ 37` являются legacy и не подменяют эти входные значения.
- **Утверждённая `curve-v1`:** скрытая стоимость следующего `+1` равна `1 / 2 / 4 / 8 / 16` для диапазонов `0–29 / 30–39 / 40–49 / 50–59 / 60–69`; поэтому `28→30` стоит `2`, а `45→47` — `8`. В интерфейсе нет XP, дробей и прогресс-бара; точная спецификация — `docs/SYSTEM_PROGRESSION.md`, исполняемая формула — `system_progression.py`.
- **Закреплённое ядро Главы 3:** вход `ОТБОР 26`, доступен только ранг `F−`, условие `3 ЧИСТЫХ ОТБОРА`, первый успешный матчевый квест и результат `ОТБОР 26 → 28`; выполненный лёгкий квест не открывает следующий ранг автоматически.
- **Пакетный режим:** за один производственный/проверочный пакет обрабатывается не больше `10` фреймов. Полный review-скролл может только соединять уже проверенные пакеты, всегда маркируется `НЕ УТВЕРЖДЕНО` и не подменяет каноническую финализацию.
- **Уникальность следующих соперников:** до генерации закрепляются отдельный паспорт формы и отдельный паспорт стадиона, один эталон формы и один establishing shot. Чёрный комплект не используется по умолчанию, а архитектура, окружение и география арены не повторяют предыдущий матч без сюжетной причины.
- **Типографика панелей:** стрелки и ромбы рисуются геометрией в `grid.py` (символы `→ ◆ ▲ ▸ ＋` в шрифте не используются).
